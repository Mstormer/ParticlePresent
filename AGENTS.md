# ParticlePresent: agent rules

ParticlePresent is a Claude skill (`particle-present/`) that turns a talk manuscript into one self-contained animated HTML presentation: WebGL particle light that morphs into a picture per slide, a 1920×1080 type stage scaled to any screen, speaker notes and speaker view, voice cues (Chrome/Edge), and an in-page editor (E) whose Save writes edits back into the file. It began as the owner's own talk deck. The owner's history and handoff notes live in the untracked `private/HANDOFF.md`.

## Layout

- `particle-present/SKILL.md`: the instructions Claude follows when using the skill (slide markup, forms, cue rules, build/check/deliver). Keep it accurate whenever behaviour changes.
- `particle-present/assets/template.html`: generated by `tools/build_template.py` from `src/` and `particle-present/assets/modules/`; the engine, editor, fonts and styles, rendered as a 7-slide sample deck.
- `src/`: the engine's editable sources; `tools/build_template.py`: the template build.
- `particle-present/assets/modules/`: presenter modules from Cinematic Deck Designer, unchanged.
- `particle-present/scripts/make_deck.py`: pours `<section>` slides into the template, picks voice-cue words, applies default fx, writes `deck.html` + `<Title> - ParticlePresent.html`.
- `particle-present/scripts/check.js`: Playwright; screenshots every slide fully built, reports page errors, edge and overlap warnings.
- `particle-present/examples/sample_slides.html`: the sample deck's slides; markup patterns.
- `~/.claude/skills/particle-present` is a symlink to `particle-present/` here, so every Claude Code session uses the working copy live. Keep the folder name `particle-present`, and keep `main` usable: do risky or multi-step work on a branch and merge only when it builds and checks clean.

## How the template works (read before touching the engine)

`template.html` holds its own source twice: the live rendered page, and a JSON string in `<script type="application/json" id="deck-src">`. `make_deck.py` reads only `deck-src` (plus `<style id="deck-fonts">`), swaps in the slides (from the first `<section class="slide"` to the last `</section>` before the `<div id="hov"` text, which now sits in an HTML comment at the end of the stage), and fills three markers that must each appear exactly once: `/*@FONTS@*/`, `"@SRC@"`, `"@EDITS@"`. Every built deck carries the full template, so any `... - ParticlePresent.html` also works as `--template`.

**The engine's source of truth is `src/` plus `particle-present/assets/modules/`; `template.html` is generated from them.** Never hand-edit `template.html` or its `deck-src`.

- `src/head.html`, `src/style.css`, `src/body.html` (viewport, stage, `<!-- @SLIDES@ -->`, the edits/src markers), `src/fonts.css` (Mona Sans etc., inlined), `src/light.js` (the WebGL light engine `Light`), `src/app.js` (navigation, effects, light image, naming list, finale, edit state, saving, and the adapters for the modules; its `// @MODULES@` line receives the modules).
- `particle-present/assets/modules/`: `deck-ui.js`, `speaker-view.js`, `deck-editor.js`, `deck-save.js` from Cinematic Deck Designer (public repo Mstormer/CinematicDeckDesigner, `cinematic-deck-designer/reference/`, same owner; the working copy sits next to this repo). **Keep them byte-identical to CDD.** When CDD changes them, copy the new files over unchanged, rebuild, and run the checks; anything ParticlePresent needs goes through the adapters in `src/app.js` (editor `sections` / `targets` plug-ins, speaker `snap`, deck-ui `onWords`, `help`, `bar`), never into the module files. Never copy anything from CDD's `reference/private/`, CinematicDeckDesignerPlus or the live-audience relay.
- Build: `python3 tools/build_template.py` joins the sources into `deck-src`, pours in `particle-present/examples/sample_slides.html` with `make_deck.py` (exactly like a user's build, default fx included) and writes `particle-present/assets/template.html`. `python3 tools/build_template.py --check` says whether `template.html` is up to date. Commit `src/`, the modules and the rebuilt `template.html` together.
- JS in `src/` and the modules must not contain `</script` or `<!--` (they are inlined; the build refuses).
- The edit state (`deck-edits`) is the modules' shared shape: `{ fx, slides: { <id>: { els: { <data-e>: {x,y,s,w,hide,html} }, notes, img, names } }, timing: { wpm, auto, over } }`. Decks saved before the modules load as they are; `timing.auto` (builds come on their own with voice off) defaults to true for them, as before.

## Build and check

```bash
python3 particle-present/scripts/make_deck.py --template particle-present/assets/template.html --slides particle-present/examples/sample_slides.html --title "Sample" --out <scratch>/out
```
- Fix every `!!` line (build-step / `[BUILD]` marker mismatch) and every `(none: clicker only)` cue.
- `--settings settings.json` overrides default fx (`speed 1.5, morph 1.5, bright 1, glow 2, bg 1.25, quality high, bar on`); `--edits` carries forward a saved `deck-edits` JSON.

```bash
node particle-present/scripts/check.js "<scratch>/out/Sample - ParticlePresent.html" <scratch>/shots
```
- Needs Node + Playwright (`require('playwright')`) with Chromium. Playwright may not be installed globally; install it into a scratch folder (`npm i playwright && npx playwright install chromium`) and run with `NODE_PATH` pointing at its `node_modules`, rather than adding it to the repo.
- Look at the screenshots yourself; a clean log is not enough for visual changes.
- Scratch work (builds, Playwright, screenshots) lives in a sibling folder `../ParticlePresent-scratch.noindex` (Playwright is installed there), not `/tmp`: a reboot can wipe `/tmp`.
- UI changes: also run CDD's kit (`reference/tests/kit/` `hud.js notes.js sv.js ed.js save.js`) against the built sample. Copy the kit into the scratch folder and change `#slides > .slide` (and `#slides [contenteditable`) to `#stage`; in `ed.js` pick the group's text as the first leaf `[data-e]` (CDD marks it `[data-et]`) and skip the "no plug-ins" assertion, since ParticlePresent supplies light plug-ins. The kit expects `__deck.maxStep(i)`, `state()`, `buildDoc()`, `hear()`, `settle()`, `busy`, which `src/app.js` provides.
- Build output and screenshots go to the scratchpad, never into the repo.

`dist/` is git-ignored. Give the user the path; `dist/` is the zip's home. GitHub releases (tag + attached zip, via `gh release create`) only when the user asks.
